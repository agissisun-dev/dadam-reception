# 문자 발송 설정 (솔라피)

앱의 해피콜·주간 관리 줄에서 [문자 보내기]를 누르면 접수실 화면에서 바로 문자가 나갑니다.
문자 업체 키를 넣기 전까지는 버튼을 눌러도 "문자 설정이 아직 안 되어 있습니다"라고만 안내합니다.

## 1. 솔라피 가입과 발신번호 등록 (원장님이 한 번)
1. https://solapi.com 회원가입 → 콘솔 로그인.
2. [발신번호 관리] → 병원 대표번호 등록. 사업자등록증과 통신서비스 이용증명원(통신사에서 발급)이 필요합니다. 승인까지 보통 1~2일.
3. [충전] 에서 소액 충전. 짧은 문자(SMS) 건당 20원 안팎, 긴 문자(LMS) 50원 안팎.
4. [API Key 관리] → 새 키 발급 → **API Key**와 **API Secret** 두 값을 복사.

## 2. Vercel에 키 넣기 (원장님이 직접, 다른 사람에게 보내지 않는다)
1. https://vercel.com → dadam-reception 프로젝트 → Settings → Environment Variables.
2. 아래 세 개를 Production에 추가. 이름 앞에 `NEXT_PUBLIC_`을 붙이면 브라우저에 노출되니 **붙이지 않는다**.

| 이름 | 값 |
|---|---|
| `SOLAPI_API_KEY` | 솔라피 API Key |
| `SOLAPI_API_SECRET` | 솔라피 API Secret |
| `SMS_SENDER_NUMBER` | 등록한 발신번호, 숫자만 (예: 0212345678) |

3. 저장 뒤 다시 배포: `npx vercel deploy --prod --yes` (환경 변수는 새 배포부터 적용됩니다).

## 3. 확인
1. 앱 해피콜 화면에서 환자 줄을 펼치고 [문자 보내기] → 받는 사람 확인 → [보내기].
2. 원장님 휴대폰을 환자 연락처로 둔 시험 환자로 먼저 보내 본다. **끝나면 시험 환자는 지운다.**
3. 보내면 그 해피콜은 "연락함(문자)"으로 기록되고, 기록 메모에 보낸 문구가 남는다. 주간 관리는 "발송함"으로 기록되고 회차가 올라간다.
4. 실패하면 화면에 "문자를 보내지 못했습니다. …"와 업체가 준 이유가 뜬다. 발신번호 미승인, 잔액 부족이 흔한 이유.

## 동작 방식 (참고)
- 브라우저 → 앱 서버(`app/api/sms/route.ts`, Vercel에 함께 배포) → 솔라피. 업체 키는 서버에만 있다.
- 서버는 로그인 토큰을 확인해 로그인한 사람만 보낼 수 있게 한다.
- 받는 번호는 휴대폰(01로 시작, 10~11자리)만. 문구는 90바이트까지 SMS, 그 위는 LMS(최대 2,000바이트)로 자동 구분. `lib/smsRules.ts`
- 솔라피 규격이 바뀌면 `app/api/sms/route.ts` 한 파일만 고치면 된다. 이 세션에서는 업체 문서 사이트에 접속할 수 없어 알려진 규격(`/messages/v4/send`, HMAC-SHA256 서명)으로 만들었다. 첫 시험 발송이 실패하면 그 화면 문구를 그대로 알려 주면 된다.

## 환자 답장
일반 문자의 답장은 병원 전화기로 온다. 앱은 보낸 기록만 남기고, 답변은 지금처럼 주간 관리의 [답변 기록]에 적는다.
카카오 알림톡으로 바꾸고 싶으면 같은 솔라피 계정에서 카카오 채널 연결과 문구 심사를 받은 뒤 서버 파일만 바꾸면 된다.

## 사적 사용 방지 (2026-09-18 추가)
- 화면에서는 그 환자의 연락처·가족 연락처만 고를 수 있고, **서버도 같은 대조를 다시 한다.** 등록 안 된 번호로는 어떤 경로로도 보낼 수 없다.
- 모든 시도(보냄·실패·거절)가 `sms_logs` 장부에 "언제·누가·어느 환자·어느 번호·문구·결과"로 남는다. 앱에서는 고치거나 지울 수 없고, [현황] 화면 아래에서 본다.
- 장부 표는 `supabase/schema-v3-4-sms-logs.sql`로 만든다 (setup-supabase.md 11절).

## 예약 자동 안내 문자 (V8, 2026-11-06 추가)
예약 화면 → [설정 (간격·안내 문구)] 에서 두 가지를 켤 수 있습니다.
- **예약이 잡히면 바로 확인 문자**: 접수실에서 잡은 예약(장부·해피콜에서 넘어온 것 포함)에 휴대폰 번호가 있으면 잡히는 순간 설정의 안내 문구로 보냅니다. 네이버 예약은 네이버가 이미 알림을 보내므로 보내지 않습니다. 실패하면 "예약은 잡혔습니다. 자동 문자는 못 보냈습니다"가 뜨고 지금처럼 복사해서 병원 휴대폰으로 보냅니다.
- **전날 오후 5시 리마인더**: 서버가 매일 한국 시간 17시에 내일 예약자(네이버 포함) 중 휴대폰 번호가 있는 분께 리마인더 문구를 보냅니다. 보낸 예약에는 "자동 문자" 표시가 남습니다.

### 필요한 것
1. 위 1절·2절의 솔라피 키 세 개 (`SOLAPI_API_KEY`·`SOLAPI_API_SECRET`·`SMS_SENDER_NUMBER`). 없으면 둘 다 "문자 설정이 아직 안 되어 있습니다"로 멈춥니다.
2. Supabase SQL Editor에서 `supabase/schema-v8-appointment-notify.sql` 실행 (설정 표에 켜기/끄기 칸, 예약 표에 리마인더 보낸 시각 칸). 실행 전에도 앱은 돌아가지만 설정 저장이 실패합니다.
3. 리마인더용 Vercel 환경 변수 세 개 (Production, `NEXT_PUBLIC_` 없이):

| 이름 | 값 |
|---|---|
| `CRON_SECRET` | 아무 긴 임의 문자열 (Vercel이 크론을 부를 때 이 값으로 신분을 밝힘). 32자 이상 권장 |
| `REMINDER_LOGIN_EMAIL` | 접수실 공용 계정 이메일 (리마인더는 이 계정으로 로그인해 그 병원 예약만 읽음) |
| `REMINDER_LOGIN_PASSWORD` | 그 계정 비밀번호 |

4. 저장 뒤 다시 배포(main에 push). `vercel.json`의 크론(매일 08:00 UTC = 한국 17:00)은 배포와 함께 등록됩니다. Vercel → 프로젝트 → Settings → Cron Jobs에서 보입니다. 무료(Hobby) 요금제는 하루 한 번 크론만 되고 시각이 한 시간 안에서 흔들릴 수 있습니다.

### 확인
- 설정에서 "바로 확인 문자"를 켜고, 원장님 휴대폰 번호로 시험 예약을 잡아 문자가 오는지 봅니다. 끝나면 시험 예약은 지웁니다.
- 리마인더는 Vercel Cron Jobs 화면에서 [Run]으로 바로 돌려 볼 수 있습니다. 응답에 `targets`(대상 수)·`sent`·`failed`가 나옵니다.
- 보낸 것·실패한 것은 모두 [현황] 아래 문자 장부에 "자동 리마인더" 처리자로 남습니다.

### 카카오 알림톡으로 바꾸기 (나중에)
같은 솔라피 계정에서 카카오 비즈니스 채널을 연결하고 문구 두 개(확인·리마인더)를 심사받은 뒤, `lib/smsServer.ts`의 보내기 한 군데만 알림톡 규격으로 바꾸면 됩니다. 심사받은 문구만 보낼 수 있어서 자리표 외의 문구 수정은 그때부터 제한됩니다.
