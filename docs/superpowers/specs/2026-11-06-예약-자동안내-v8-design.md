# 다담 접수실 앱 V8 예약 자동 안내 문자 설계

작성일: 2026-11-06
출처: 사용자 요청("예약을 하면 카톡이나 문자로 예약 자동 안내문자를 보내는 것을 세팅하려고 해"). V7 예약차트의 "자동 발송 없음"을 이번 결정으로 바꾼다.
브레인스토밍 결정(2026-11-06): ① 잡을 때 바로 + 전날 한 번 더 ② 일반 문자로 시작, 카톡 알림톡은 나중에 ③ 확인 문자는 접수실에서 잡은 것만(네이버 제외), 리마인더는 네이버 포함.

## 1. 목표와 핵심 질문
접수실이 예약을 잡은 뒤 병원 휴대폰으로 따로 치는 일을 없애고, 전날 리마인더로 노쇼를 줄인다.
**핵심 질문:** 빈 자리를 눌러 이름만 넣으면 환자 휴대폰에 확인 문자가 가고, 전날 오후 5시에 리마인더가 알아서 가는가. 그리고 누구에게 무엇이 나갔는지 장부에 남는가.

## 2. 규칙 (`lib/appointmentNotifyRules.ts`, 테스트 있음)
- 확인 문자: 설정 `auto_notify` 켜짐 + 출처가 접수실·장부·해피콜 + 예약 상태 + 휴대폰 번호(01…) + 아직 안내 안 보냄.
- 리마인더: 설정 `remind_enabled` 켜짐 + 내일(한국 날짜) 예약 + 예약 상태 + 휴대폰 번호 + 아직 리마인더 안 보냄. 출처 불문.
- 실패하면 예약은 그대로 두고 화면에 알린다. 자동으로 다시 보내지 않는다(접수실이 복사해 보냄).

## 3. 구조
| 부분 | 파일 | 역할 |
|---|---|---|
| 표 | `supabase/schema-v8-appointment-notify.sql` | 설정 3칸, 예약 2칸 |
| 서버 공통 | `lib/smsServer.ts` | 솔라피 호출, 장부 기록, 받는 번호 대조(환자 또는 예약 기준) |
| 화면에서 보내기 | `app/api/sms/route.ts` | 기존 + `appointmentId`로도 대조 |
| 전날 리마인더 | `app/api/appointments/remind/route.ts`, `vercel.json` | 매일 08:00 UTC(17:00 KST) 크론. `CRON_SECRET` 대조, 접수실 계정으로 로그인(RLS 그대로, anon 키만) |
| 잡을 때 | `lib/appointmentNotify.ts`, `app/appointments/page.tsx` BookBox | 저장 직후 보내고 "자동 문자"로 기록. 잡힘 띠에 결과 표시 |
| 설정 | `app/appointments/page.tsx` SettingsBox | 켜기 두 개 + 리마인더 문구 |

원칙: 자동 발송도 같은 서버 경로를 지나 같은 대조(예약에 적힌 번호 또는 연결된 환자 번호)와 같은 장부(`sms_logs`)를 거친다. 서비스 키는 쓰지 않는다.

## 4. 확인 항목 (qa)
- SQL 실행 → 설정에서 "바로 확인 문자" 켜기 → 시험 예약(원장 휴대폰) → 문자 도착, 띠에 "자동으로 보냈습니다", 문자 장부에 한 줄.
- 네이버 붙여넣기로 들어온 예약은 확인 문자가 안 간다.
- Vercel Cron [Run] → 내일 예약자에게 리마인더, 예약에 "자동 문자", 장부에 "자동 리마인더".
- 키 없을 때: 예약은 잡히고 "자동 문자는 못 보냈습니다: 문자 설정이 아직…"이 뜬다.
