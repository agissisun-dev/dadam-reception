# 수납 장부 (오늘 장부) V4 — 설계

작성 2026-10-02. 사용자(구디) 결정에 따라 엑셀 「일일매출장부」를 앱으로 옮긴다. 돈 칸까지 앱에 넣고, 수납 한 줄이 환자·처방·해피콜·약장 나감을 자동으로 만든다. 화면안: https://claude.ai/artifact/WqHVrbA5JHpWiezLM2wiW4

## 1. 목적과 범위

- **목적**: 접수실이 창 하나(앱)만 열고 수납을 적게 한다. 엑셀 장부 창이 없어진다. 전자차트(보험 청구)는 남는다.
- **달라지는 규칙**: "금액 칸은 안 넣는다"(현황 V3-3) 규칙을 **폐기**한다. 매출은 장부에서 나오고, 현황에 매출이 보인다.
- **범위 안**: 오늘 장부 화면(입력·목록·합계·지출·마감), 항목 사전(약어 표), 약어 → 항목 변환, 탕약 → 처방·해피콜 자동, 약장 품목 → 나감 자동, 리뷰 증정, 정정 줄, 월별 엑셀 내려받기, 현황의 매출·항목 집계.
- **범위 밖**: 예약차트, 탕전실 화면, 솔라피, 2025년 이전 장부 이관, 전자차트 연동. 보험 청구 금액(공단 부담금)은 다루지 않는다 — 엑셀도 환자 부담금만 적었다.

## 2. 엑셀에서 읽은 구조 (2025년 일일장부(다담S).xlsx, 9월 시트)

- 하루 = 56줄 블록. 1행 제목 `* 일일매출장부 ( 2025년 09월 01일) *월`, 2~3행 머리글, 4~53행 환자 50줄, 54행 합계(현금·현영·카드·소계, 지출 합계), 55~56행 입금·잔액.
- 환자 줄 열: `번호 | 성함 | 구분 | 현금 | 현영 | 카드 | 소계 | 기타 | 지출내용 | 금액`. 뒤 달 시트는 L~N열에 `합계` 칸이 더 있다.
- `구분`: 1종, 2종 등 보험 종별. 비면 일반.
- `현영` = 현금영수증 발행한 현금. 소계 = 현금 + 현영 + 카드.
- `기타` = 그날 진료 내용을 쉼표로 이어 쓴 약어. 괄호 숫자는 **금액(만원)**이다: `일반(42)` = 일반 탕약 42만원, `발효(48)` = 발효탕약 48만원. `#2` = 2회로 나눠 나감(분할 수령). 포 수는 장부에 없다.
- 지출은 같은 블록 오른쪽에 `지출내용 | 금액`으로 적는다(시재·간식비 등).

## 3. 화면

### 3-1. 오늘 장부 `/ledger`
상단 메뉴 첫 자리에 **오늘 장부**. 첫 화면(달력)은 그대로 둔다.

1. **날짜 줄**: ◀ 날짜 ▶ 오늘 · 마감 전/마감됨 표시. 오른쪽에 현금·현영·카드·소계·지출 합계 칸.
2. **새 줄**(엑셀과 같은 순서): 성함 · 구분 · 현금 · 현영 · 카드 · 기타 · 처리자 · [저장]. 탭으로 넘어간다. 엔터로 저장.
   - 성함 칸: 치면 환자 목록에서 이름이 뜬다(가린 연락처·질환·마지막 처방 보여 줌). 고르면 환자가 연결된다. 안 고르면 이름만 글로 남는다(치료만 받은 환자는 연결 없어도 됨).
   - 기타 칸 아래 **알아본 항목** 칩: 치료(회색) · 탕약(주황) · 약장 품목(파랑). 모르는 조각은 붉은 점선 칩 "모르는 말 — 눌러서 정하기".
   - 탕약 칩이 있으면 **포 수 버튼**(20·35·40·70·직접)과 하루 포수(기본 2)가 뜬다. 고르면 오른쪽에 "처방 1건 → 해피콜 1차 M/D · 2차 M/D"가 미리 보인다. 포 수 없이 저장하면 줄에 "포 수 없음" 표시가 남고 처방·해피콜은 만들지 않는다(나중에 줄에서 포 수 넣기 → 그때 생성).
   - 탕약 칩이 있는데 환자가 연결되지 않았으면: 같은 이름 환자가 있으면 고르게 하고, 없으면 연락처 11자리를 묻는 작은 칸이 뜬다 → 새 환자 등록(질환은 기본 일반, 나중에 환자 상세에서 고침).
   - 약장 칩: 수량이 있으면 그 수만큼 나감. 금액이 0이고 "리뷰" 조각이 있으면 사유 **리뷰 증정**, 아니면 **판매**.
3. **오늘 줄 목록**: 번호 · 성함 · 구분 · 현금 · 현영 · 카드 · 소계 · 항목 칩 · 따라온 것(해피콜 날짜 / 약장 −N / 포 수 없음) · 처리자. 맨 아래 합계 줄과 항목별 건수 요약.
   - 마감 전: 줄을 눌러 고치거나 지울 수 있다(지우면 따라온 처방·해피콜·약장 나감도 같이 지운다 — 단, 해피콜에 연락 기록이 있으면 못 지우고 안내).
   - 마감 뒤: 고치기·지우기 불가. **[정정 줄 넣기]**만 가능.
4. **지출**: 내용 · 금액 · [추가]. 마감 전엔 지울 수 있다.
5. **오늘 마감**: 종이 장부와 소계를 맞춘 뒤 누른다. 처리자 이름을 고른다. 마감하면 그날 줄·지출이 잠긴다. 마감 취소는 없다(정정 줄로).
6. **엑셀로**: [이 달 전체] [오늘만]. 지금 쓰는 일일장부 모양 그대로(한 시트에 하루 56줄 블록) 내려받는다. 세무사용·병행 기간 대조용.

### 3-2. 정정 줄
마감된 날의 줄이 틀렸을 때. 원래 줄을 고르고 "현금 −11,000 / 카드 +11,000"처럼 차이만 적는다. 사유 필수, 처리자 필수. 목록에 원래 줄 아래 "정정" 표시로 붙는다. 합계는 정정을 더한 값. 항목(탕약·약장)의 정정은 하지 않는다 — 처방은 환자 상세의 [수령일 바꾸기], 약장은 약장 화면에서 실사로 맞춘다.

### 3-3. 항목 사전 `/ledger/codes`
약어 표. 접수실이 고칠 수 있다. 열: 약어 · 이름 · 묶음(탕약/약장/치료/엑스제/기타) · 약장 품목 연결 · 사용 중. 새 약어는 "모르는 말" 칩에서 그 자리에서 추가된다.

### 3-4. 현황에 더하는 것
- 월별 매출: 현금·현영·카드·소계, 지출, 일 평균. 최근 12개월 그래프에 소계 추가.
- 항목별 건수: 탕약(보험/일반/발효) 건수와 금액, 공진단·소합원·경옥환 개수, 전침·습부항·약침·수승화강 건수, 엑스제 일수.
- 리뷰 증정 건수(약장 장부와 같은 숫자).
- 매출 부분은 화면에서 접혀 있고 "매출 보기"를 눌러야 펼쳐진다(접수실 PC에 늘 떠 있지 않게). 비밀번호는 묻지 않는다 — 사용자 확인 필요(§9).

### 3-5. 첫 화면
달력 아래 요약에 "오늘 장부 N줄 · 소계 ₩" 한 줄과 "마감 안 한 날 M일" 경고(어제까지 마감 안 된 날이 있으면).

## 4. 약어 → 항목 변환 규칙 (`lib/ledgerRules.ts`, 순수 함수 + 테스트)

입력 `기타` 글을 쉼표(`,`)로 나눈다. 조각마다 공백을 지우고 아래 순서로 본다.

| 모양 | 뜻 | 예 |
|---|---|---|
| `약어` | 항목 1건 | `습`, `전`, `V`, `수승화강`, `S거즈` |
| `약어N` / `약어NT` / `약어N알` | 항목 N개 | `공진단5T`, `소합원3T`, `V2` |
| `약어(N)` | 항목, 금액 N만원 | `일반(42)`, `발효(48)`, `스킨(5)` |
| `약어(N.#M)` / `약어(N)#M` | 금액 N만원, M회 분할 수령 | `일반(42.#2)` |
| `약어N일` | 엑스제 N일분 | `오적2일`, `향사평위2일` |
| `mo-X` / `mo-X*Y` | mo 항목, 용량 X (Y회) — 글자 그대로 보관 | `mo-0.6`, `mo-0.6*2` |
| `보험(처방)` | 보험 탕약 1건 (금액은 현금/카드 칸) | |
| `리뷰` | 이 줄의 약장 나감 사유를 리뷰 증정으로 | `소합원3T,리뷰` |

- 약어는 사전(`ledger_codes`)에서 찾는다. 대소문자·앞뒤 공백 무시. 없으면 `unknown`으로 돌려주고 화면이 붉은 칩을 띄운다.
- 사전 묶음(group): `decoction`(탕약 → 처방·해피콜) · `cabinet`(약장 품목 → 나감) · `treatment`(치료 → 세기) · `extract`(보험 엑스제 → 세기, 일수) · `other`(세기만, 예: 보험서류발급).
- 변환 결과: `{ code, name, group, qty, amount(원), days, split, raw, cabinet_item_id?, unknown? }[]`.
- 원문은 그대로 `note_raw`에 남긴다. 엑셀 내려받기는 원문을 쓴다.

**탕약 → 처방**: 포 수·하루 포수를 받아 `일수 = 올림(포 ÷ 하루 포수)`, 수령일 기본 **오늘**(탕전실 화면이 생기면 거기서 확정). 분할 수령(`#2`)은 처방 메모에 "2회 분할"로 남기고 해피콜은 지금 규칙대로 잡는다. 2회분 받은 날을 넣는 기능은 탕전실 화면과 함께 만든다(이번 범위 밖). 해피콜은 `planHappyCalls` 그대로.

**약장 품목 → 나감**: `recordOut({ item_id, qty, purpose: 'sale' | 'review', patient_id, patient_name, staff_name, memo: '장부 #줄번호' })`. 장부 줄과 약장 장부 줄을 서로 연결(`ledger_items.cabinet_move_id`).

## 5. 데이터 (Supabase, `supabase/schema-v4-ledger.sql`)

```
ledger_codes        약어 사전
  id, code text unique (대소문자 무시 인덱스), name text, "group" text check in
  ('decoction','cabinet','treatment','extract','other'), cabinet_item_id int null → cabinet_items,
  decoction_kind text null ('insurance','general','fermented'), active bool, sort_order int, created_at

ledger_days         하루 마감
  day date pk, closed_at timestamptz null, closed_by text null, memo text null

ledger_entries      환자 줄
  id, day date, seq int (그날 번호), patient_id int null → patients, patient_name text,
  insurance_kind text null (구분), cash int default 0, cash_receipt int default 0 (현영), card int default 0,
  note_raw text (기타 원문), memo text null, staff_name text,
  kind text check in ('normal','correction') default 'normal', corrects_id int null → ledger_entries,
  correction_reason text null, created_at, updated_at
  unique (day, seq) — 정정 줄은 seq null 허용 안 함 → 정정은 그날 마지막 번호+1

ledger_items        줄 안의 항목
  id, entry_id → ledger_entries (cascade), code text, name text, "group" text, qty int default 1,
  amount int null (원), days int null, split int null, raw text,
  prescription_id int null → prescriptions, cabinet_move_id int null → cabinet_moves, created_at

ledger_expenses     지출
  id, day date, title text, amount int, staff_name text, created_at
```

- RLS: authenticated 읽기·쓰기. **마감된 날 잠금**: `ledger_entries`·`ledger_items`·`ledger_expenses`의 update/delete 정책에 `not exists (select 1 from ledger_days d where d.day = <row.day> and d.closed_at is not null)`. insert는 마감 뒤에도 `kind='correction'`과 지출은 허용하지 않는다(정정 줄만 허용: `kind='correction'` 조건). `ledger_days`는 insert·update(closed_at null → 값)만, 되돌리기 불가.
- 처방·해피콜·약장 나감은 기존 표를 그대로 쓴다. `prescriptions`에 `ledger_entry_id int null` 열을 더해 어디서 왔는지 남긴다.
- 사전 초기값: §8의 약어 표를 SQL `insert`로 넣는다(확인 뒤).

## 6. 코드 구조

- `lib/ledgerRules.ts` — 약어 파싱, 합계, 번호 매기기, 엑셀 블록 배치 계산(순수). 테스트 `lib/ledgerRules.test.ts`.
- `lib/ledger.ts` — 읽기·쓰기: `loadDay(day)`, `saveEntry(input, items, {packs, perDay})`(처방·해피콜·약장 나감까지 한 번에; 실패하면 만든 것 되돌리기 — Supabase RPC `ledger_save_entry`로 한 트랜잭션에 처리), `updateEntry`, `deleteEntry`, `addExpense`, `closeDay`, `addCorrection`, `listCodes`, `upsertCode`.
- `lib/ledgerExport.ts` — exceljs로 월 시트 생성(하루 56줄 블록, 머리글·합계 수식 포함). 브라우저에서 내려받기.
- `app/ledger/page.tsx` — 오늘 장부. `components/LedgerEntryForm.tsx`(새 줄 + 칩 + 포 수), `components/LedgerTable.tsx`, `components/LedgerCodeChips.tsx`.
- `app/ledger/codes/page.tsx` — 항목 사전.
- `app/stats` — 매출·항목 집계 추가(`lib/statsRules.ts`에 순수 함수 추가).
- `components/AppHeader.tsx` — "오늘 장부" 메뉴 첫 자리.
- 트랜잭션: 한 줄 저장이 표 4~5개를 건드리므로 Postgres 함수 `ledger_save_entry(jsonb)`로 묶는다(security invoker, RLS 적용). 실패하면 아무것도 남지 않는다.

## 7. 전환·운영

- **10월은 엑셀과 병행**: 샘이 앱에 적고, 하루 끝에 [오늘만] 엑셀로 받아 종이·엑셀과 소계를 맞춘다. 11월부터 앱만.
- **지난 달 이관**: 2026년 1~9월 엑셀을 앱에 넣을지는 사용자 결정(§9). 넣는다면 줄 단위로 `note_raw`만 넣고 항목 변환은 하지 않는다(해피콜·약장이 과거분까지 생기면 안 되므로). 매출 현황만 채우는 용도.
- **서버가 안 될 때**: 종이 장부에 적고 다음 날 날짜를 지정해 넣는다(날짜 ◀로 가면 됨).
- **백업**: 매주 월요일 "엑셀 전체 내려받기"를 업무 틀로 등록(업무 등록 → 틀).
- **개인정보**: 장부에 환자 이름이 들어가지만 이미 patients에 있는 범위. 연락처는 넣지 않는다. 매출 숫자는 현황에서 접어 둔다.

## 9. 사용자 확인이 필요한 것

1. 현황의 매출 칸을 접어 두기만 할지, 원장 비밀번호를 한 번 더 물을지.
2. 2026년 1~9월 엑셀을 앱에 넣을지(매출 현황용, 항목 변환 없음), 아니면 10월부터만 할지.
3. 마감 뒤 수정 불가 + 정정 줄 방식이 접수실에 맞는지. 마감 취소는 두지 않는다.
4. 약어 표(§8)의 뜻과 묶음. 특히 V·mo·S거즈·CS·T침·기타.
5. 탕약 수령일 기본값 "오늘"이 맞는지(택배는 2~3일 뒤). 기본을 "오늘"로 두고 줄에서 바꿀 수 있게 할지, 매번 묻게 할지.
6. 장부에서 환자를 연결할 때 연락처를 묻는 것이 수납 중에 부담인지. 부담이면 "포 수 없음"처럼 "환자 연결 안 됨"으로 두고 나중에 환자 화면에서 연결.
