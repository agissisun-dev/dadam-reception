# 다담 접수실 앱 V3-6 약장 설계

작성일: 2026-09-28
출처: 사용자 요청("외용제·공진단·경옥환 같은 따로 챙겨야 할 약을 관리하는 창. 고가약인데 신뢰로만 진행되고 있어 누가 한두 알 가져가도 모르고, 외용제 유통기한은 직접 가서 보지 않으면 모른다")
브레인스토밍 결정(2026-09-28):
- 이름은 **약장**. 약과 외용제(화장품)가 한 장에 있고, 목록은 접지 않고 쭉 펼치며 **색으로만 구분**(약 초록, 외용제 파랑).
- 나갈 때 **품목·수량·환자**까지 기록. 실사는 **입고할 때마다**(그 외 [세어 넣기]로 언제든).
- 품목 9개로 시작: 약 = 대보공진단·사향공진단·경옥환·소합원, 외용제 = 아토베리어로션·선크림·퓨어스킨·세안제·카밍젤. 접수실이 앱에서 추가·수정.
- 탕전실 약재는 이번에 안 만든다(보류). 같은 틀로 확장 가능하게만 둔다.

## 1. 목표와 핵심 질문

앱이 도난을 막지는 못한다. 앱이 하는 것은 셋이다.
1. 모든 들어옴·나감에 이름과 시각이 남고, 앱에서 고치거나 지울 수 없다.
2. "있어야 할 수"를 항상 보여 준다.
3. 세어 넣으면 차이가 붉게 뜨고 사유가 남아, 어느 근무일에 났는지 좁혀진다.

**핵심 질문:** 접수실이 공진단 하나를 드릴 때 3번 눌러 기록할 수 있고, 원장이 약장 화면만 보고 "몇 개 있어야 하는데 몇 개 있는지"와 "곧 버릴 게 있는지"를 알 수 있는가.

## 2. 데이터 (`supabase/schema-v3-6-cabinet.sql`)

| 표 | 칸 | 뜻 |
|---|---|---|
| `cabinet_items` | id, name, kind('medicine'/'topical'), min_stock(부족 기준, 기본 0), active, sort_order, created_at | 품목. 접수실이 고칠 수 있다(auth all). 삭제 대신 active=false. |
| `cabinet_moves` | id, item_id, kind('in'/'out'/'count'/'discard'), qty, expiry(date, in 전용), patient_id(null 가능), patient_name, staff_name, memo, diff(count 전용: 센 수 − 있어야 할 수), created_at | 장부. **넣기만 가능, 수정·삭제 불가**(RLS select+insert). |

있어야 할 수 = 장부를 시간순으로 따라간 값. in +qty, out/discard −qty, count는 그 시점의 값을 qty로 **덮어쓴다**(차이는 diff에 남김).
유통기한: in 줄이 곧 "입고 묶음". 오래된 묶음부터 나간 것으로 보고, 지금 수를 최근 묶음부터 채워 넣어 남은 묶음을 구한다. 그중 가장 빠른 기한이 "가장 빠른 유통기한".

## 3. 규칙 (`lib/cabinetRules.ts`, 테스트)

- `expectedStock(moves)`: 위 계산.
- `remainingLots(inMoves, stock)`: 최근 입고부터 stock만큼 배분 → 남은 묶음 [{expiry, qty}].
- `nearestExpiry(lots)`: 남은 묶음 중 가장 빠른 기한(없으면 null).
- `expiryStatus(expiry, today)`: 지남 → "expired", 30일 안 → "soon30", 60일 안 → "soon60", 아니면 null.
- `countDiff(expected, counted)` = counted − expected. 0이 아니면 사유 필수.

## 4. 화면

**[약장] 메뉴 (`/cabinet`)**
- 품목 9줄이 접히지 않고 쭉. 줄 앞 색 점(약 초록 #16863b, 외용제 파랑). 줄에 이름, **지금 수**(부족이면 붉게 "부족"), 가장 빠른 유통기한과 D-일(30일 안 붉게, 60일 안 노랗게, 지났으면 "폐기 필요" 붉게).
- 줄마다 **[나감] [입고]** 버튼이 바로 있다.
  - 나감: 수량(기본 1) → 환자(이름·연락처로 검색해 고름, 없으면 이름만 입력) → 담당자 → 저장.
  - 입고: ① "지금 몇 개 남았나요?" 세어 입력 → 있어야 할 수와 차이를 보여 주고, 차이가 있으면 사유 필수(count 줄 기록) → ② 새로 들어온 수량·유통기한·메모 → 저장(in 줄 기록).
- 줄을 펼치면 [세어 넣기](count만) [폐기](수량·사유, discard) 와 이 품목의 최근 기록.
- 화면 아래 "최근 기록" 30줄: 언제·무엇·종류·수량·환자·담당자·사유. count 줄에 차이가 있으면 붉게.
- [품목 관리]: 이름·구분·부족 기준 추가·수정, 사용 안 함 처리.

**첫 화면**: 요약 줄에 "약장 기한 임박 N · 부족 M" 링크. 둘 다 0이면 안 보인다.

**현황**: "약장" 묶음 — 이번 달 나간 수(품목별), 세어 맞춤 차이 난 횟수·수량, 기한 30일 안 품목.
