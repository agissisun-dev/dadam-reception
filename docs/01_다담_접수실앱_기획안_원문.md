# 다담 접수실 앱 기획서 v1

작성일: 2026-09-09
대상: 노원다담한의원 · 다담에스한의원 접수실
사용자: 접수실 2명 + 원장님 부부
실행 환경: 원내 PC (원내망)
구현 도구: Claude Code (별도 Next.js 앱)

> 앞서 만든 `다담-진료실앱-기획서-v1.md`는 **보류**한다.
> 진료실에서는 차트에 "몇 번 영상"이라고 적으면 접수실이 카카오톡으로 보내는 흐름이 이미 돌아가고 있다. 여기에 앱을 끼워 넣으면 진료 시간만 뺏긴다.

---

## 1. 이 앱의 정체

문자 발송기가 아니다. **접수실의 오늘 할 일 화면**이다.

지금 놓치고 있는 일들은 성격이 하나로 묶인다.

| 업무 | 주기 | 놓치는 이유 |
|---|---|---|
| 내원 끊긴 환자 주 1회 관리 문자 | 환자별 주 1회 | 누구 차례인지 기억에 의존 |
| 명절 안내 · 선물 | 명절 4주 전 / 1주 전 | 날짜를 놓친다 |
| 다음 달 달력 카카오 채널 업로드 | 매월 말 | 월말에 바쁘면 밀린다 |
| 재내원 문자 | 탕약 소진 3일 전 | 기억나면 한다 |

전부 **오늘 뭘 해야 하는지 아무도 안 알려줘서** 놓치는 일이다.
아침에 앱을 켜면 오늘 할 일이 떠 있고, 처리하면 사라진다. 그게 전부다.

## 2. 기능 1 — 주간 환자 관리 (최우선)

피부·소화기 환자 중 내원이 이어지지 않는 분들에게 주 1회 상태 확인 · 식단 점검 · 내원 안내를 보낸다.
현재 관리 대상 10~30명 규모.

### 동작

1. 환자를 앱에 등록한다 (이름, 연락처, 질환, 관리 유형)
2. 정해진 요일에 **이번 주 대상 명단**이 뜬다
3. 각 환자마다 문구가 준비되어 있다 — 회차와 질환에 맞게
4. 접수실이 확인 → 복사 → 카카오 채널에서 발송 → 앱에서 [발송함] 체크
5. 최근 내원한 분이 명단에 있으면 [내원함 · 건너뜀]을 누른다. 다음 주로 넘어간다

**내원 여부를 앱에 따로 입력하지 않는다.** 발송 시점에 접수실이 알아보고 건너뛰면 된다.
이중 입력을 만들면 앱이 짐이 된다.

### 주기 설정

- 기본은 **요일 고정** (예: 매주 화요일에 전원 명단이 한 번에 뜸). 10~30명이면 몰아서 처리하는 게 낫다
- 환자별로 다른 요일 · 다른 주기(2주 1회 등)도 설정 가능

### 문구 준비

- 질환군별 템플릿: 피부(사진 요청) / 소화기(식단 점검) / 공통(내원 안내)
- **회차에 따라 문구가 달라진다.** 1주차, 2주차, 3주차가 같은 문장이면 성의 없어 보이고 환자도 안 읽는다
- 발송 화면에 **지난 회차에 보낸 문구와 환자 답변 메모**가 같이 보인다. 이게 없으면 매주 똑같은 말만 나간다
- 문구는 복사 전에 한 줄 수정 가능

### 자동 정리

- **4주 연속 무응답 → '휴면'으로 자동 이동.** 목록에서 빠진다. 안 그러면 명단이 답 없는 이름으로 가득 차고, 그러면 아무도 명단을 안 본다
- 연락 원치 않는다고 하면 즉시 제외 (영구)
- 다시 내원하면 자동 복귀

### 환자 답변 처리

환자가 사진이나 식단을 보내오면 원장님이 보셔야 한다.

- 접수실이 답변 받은 내용을 한 줄로 기록 → **'원장님 확인 대기'**로 표시
- 원장님이 확인하고 지시사항을 남기면, 다음 발송 문구에 그게 반영된다
- 이 왕복이 되어야 관리 문자가 형식적인 인사에서 실제 진료로 바뀐다

*(2단계에서 붙여도 된다. 1단계는 발송까지만.)*

## 3. 기능 2 — 반복 업무 알림

환자 정보가 전혀 필요 없다. 달력만 있으면 된다. **가장 빨리 만들 수 있는 부분이다.**

### 등록하는 것

| 업무 | 알림 시점 | 딸려 나오는 것 |
|---|---|---|
| 설·추석 안내 | 4주 전 / 1주 전 | 안내문 초안, 작년에 보낸 문구 |
| 명절 선물 준비 | 4주 전 | 작년 발주처 · 수량 메모 |
| 다음 달 달력 업로드 | 매월 25일경 | 지난달 달력 이미지, 업로드 체크 |
| 휴진 공지 | 연휴 2주 전 | 홈페이지 · 네이버 플레이스 수정 체크 |

### 핵심 요건

- **연간 자동 반복.** 올해 항목이 내년 같은 시기에 다시 뜬다
- **작년 기록이 따라온다.** 작년에 보낸 안내문, 작년 발주 수량, 그때 남긴 메모.
  이게 인수인계의 실체다. 담당자가 바뀌어도 작년 것을 보고 그대로 하면 된다
- **완료 로그**: 누가 언제 처리했는지
- 항목은 접수실이 직접 추가·수정할 수 있어야 한다 (개발자 없이)

여기서부터 시작해서 파트별 업무 매뉴얼로 넓혀가면, 원래 만들려던 병원 운영 매뉴얼이 자연스럽게 완성된다.

## 4. 기능 3 — 재내원 문자

탕약 소진 3일 전 안내.

- **처방하는 날 한 건씩 등록한다.** 이름·연락처·처방일수 세 칸, 건당 10초
- 과거 데이터가 필요 없다. 오늘부터 쌓으면 3주 뒤부터 대상자가 뜬다
- 한 번 등록된 환자는 이름 두 글자만 쳐도 뜬다. 재처방은 처방일수만 바꾸면 끝
- 제외: 이후 재처방 있음 / 다음 예약 잡혀 있음 / 종결 / 수신거부

전자차트 연동이 되면 이 등록 단계가 사라진다. 그전까지 수기로 돌려도 충분히 굴러간다.

## 5. 카카오 채널 발송 — 현실적인 이야기

원장님 선택은 "우선 복사, 나중에 연동"이었다. 그게 맞다. 이유를 적어둔다.

카카오톡으로 보내는 메시지는 종류에 따라 조건이 다르다. 알림톡·친구톡 같은 발송 API는 사업자 인증과 **템플릿 사전 승인**이 필요하고, 승인된 템플릿은 문구를 자유롭게 못 바꾼다. 반면 지금 접수실이 하고 있는 것처럼 채널에서 환자와 대화하듯 보내는 메시지는 자동화 대상이 아니다.

그런데 이 앱에서 보내는 관리 문자는 **환자마다 문구가 달라야** 의미가 있다. 지난주에 뭘 말했는지에 따라 이번 주 문장이 달라져야 하니까.

**그래서 복사·붙여넣기가 타협이 아니라 정답에 가깝다.**
앱이 하는 일은 "누구에게, 무슨 내용을 보낼지 정확히 준비해서 대기시키는 것"이고, 붙여넣기 자체는 3초다. 놓치는 걸 막는 게 목적이지 클릭 수를 줄이는 게 목적이 아니다.

> **확인 필요**: 지금 쓰시는 카카오 채널이 어떤 형태인지(채널 관리자센터 직접 발송 / 외부 발송 대행 서비스). 발송 대행을 쓰고 계시면 API가 열려 있을 수 있어 2단계 연동이 쉬워진다.

문자(SMS/LMS)는 발송 API 연동이 카카오보다 훨씬 수월하다. 카카오톡을 안 쓰시는 환자에게는 이쪽이 대안이 된다.

## 7. 개인정보 — 원칙 수정

앞선 기획서에서 "차트번호만 저장하고 연락처는 발송 순간에만 조회"라고 썼다.
**그건 전자차트 연동이 될 때만 성립하는 이야기였다.** 수기 입력이면 조회해 올 곳이 없으므로 연락처가 앱에 살아 있어야 한다.

현실적으로 지킬 수 있는 선으로 바꾼다.

- 이름·연락처는 **암호화해서 저장**
- 화면·목록·로그에는 **항상 마스킹**
- 관리 종료(휴면 · 종결) 후 일정 기간이 지나면 **연락처만 자동 삭제.** 발송 이력은 남는다
- **원내망 전용**, 외부 접속 불가
- **개인별 계정.** 공용 계정 금지 — 누가 발송했는지 남아야 한다
- 관리 문자에 이벤트·할인 문구가 들어가는 순간 광고성 메시지가 되어 수신동의·야간발송 규정이 적용된다. 문구를 치료 안내 범위 안에 둔다
- 수신거부 처리 경로 확보

"아예 안 갖는다"에서 **"최소한만, 짧게 갖는다"**로 목표를 옮긴 것이다.

## 9. 개발 순서

| 단계 | 내용 | 예상 |
|---|---|---|
| 1 | 반복 업무 알림 (환자 정보 불필요) | 1~2일 |
| 2 | 환자 등록 + 주간 관리 명단 + 문구 준비 + 발송 체크 | 3~4일 |
| 3 | 회차별 문구 · 지난 이력 표시 · 자동 휴면 처리 | 2일 |
| 4 | 재내원 문자 (처방 등록 + 대상 계산) | 2일 |
| 5 | 환자 답변 기록 → 원장님 확인 대기 → 지시사항 반영 | 2일 |
| 6 | (선택) 카카오 · 문자 발송 API 연동 | 별도 |

1단계를 먼저 두는 이유는 **환자 정보를 안 건드리고 앱이 돌아가는 걸 먼저 확인**하기 위해서다.
접수실이 "이거 쓸 만하네"를 느끼는 데 이틀이면 충분하고, 그다음에 환자 데이터를 넣는 게 순서다.

## 10. Claude Code 첫 프롬프트

```
새 Next.js 앱 '다담 접수실'을 만든다. 원내 PC에서 쓰는 접수실 업무 관리 앱이다.

1단계 범위: 반복 업무 알림만. 환자 정보는 아직 다루지 않는다.

기능:
- 반복 업무 등록: 제목, 담당 파트, 알림 시점, 체크리스트, 안내문 초안
- 알림 시점 규칙: 특정 날짜 기준 N주 전 / 매월 N일 / 매년 특정일
- 첫 화면은 '오늘 할 일'. 오늘 알림이 뜬 업무만 보인다
- 업무를 열면 체크리스트와 안내문 초안이 보이고, 완료 처리하면 목록에서 사라진다
- 완료 시 메모와 파일 첨부 가능 (올해 보낸 안내문 등)
- 연간 반복: 완료해도 내년 같은 시기에 다시 생성된다
- 작년 기록(메모·첨부·당시 문구)이 올해 항목에 함께 표시된다  ← 중요
- 항목 추가·수정은 접수실이 화면에서 직접 한다

기본 등록 항목:
- 설/추석 안내 (명절 4주 전, 1주 전)
- 명절 선물 준비 (4주 전)
- 다음 달 달력 카카오 채널 업로드 (매월 25일)
- 연휴 휴진 공지 (연휴 2주 전)

첨부한 기획서(다담-접수실앱-기획서-v1.md)의 §3, §6을 참고할 것.
```

## 11. 나중에 붙일 후보

- 파트별 오픈·마감 체크리스트 → 4개 파트 전체로 확장하면 병원 운영 매뉴얼이 된다
- 신입 온보딩 트랙
- 탕전실 약재·소모품 발주 주기 알림
- 노쇼·예약취소 후속 관리
- 전자차트 연동 (수기 등록 대체)
- 지표: 관리 문자 발송 대비 재내원 전환율 — 이게 보이면 이 앱의 가치가 숫자로 증명된다
- 진료 중 환자 질문 → 콘텐츠 소재 (원장님이 원하실 때)
