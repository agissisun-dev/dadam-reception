# 다담 접수실 앱 V3-1 화면에서 문자 보내기 설계

작성일: 2026-09-17
출처: 사용자 요청("해피콜 목록만 뜨는 게 아니라 문구를 수정해서 앱에서 전송을 누르면 바로 문자가 가게. 지금은 휴대폰으로 따로 쳐서 보내야 하니까")
브레인스토밍 결정: 정해진 날에 자동으로 보내지 않는다. 접수실이 줄을 보고 문구를 고친 뒤 [문자 보내기]를 눌러야 나간다. 채널은 일반 문자(SMS/LMS)로 시작, 업체는 솔라피. 알림톡은 나중에.

## 1. 목표와 핵심 질문
복사 → 휴대폰에 붙여넣기 → 보내기 세 단계를 앱 안의 한 번 누르기로 줄인다.
**핵심 질문:** 접수실이 해피콜 줄에서 문구를 확인·수정하고 [보내기]를 누르면 환자 휴대폰에 그 문구가 도착하고, 앱에는 보낸 기록이 남는가.

## 2. 데이터
표 변경 없음. 해피콜은 `contact_logs`(action=contacted, channel=sms, memo=보낸 문구), 주간 관리는 `weekly_contacts`(action=sent, message=보낸 문구)에 지금 규칙 그대로 남긴다.

## 3. 구조
| 부분 | 파일 | 역할 |
|---|---|---|
| 규칙 | `lib/smsRules.ts` (+test) | 바이트 길이, SMS/LMS 구분, 받는 번호·문구 검사 |
| 브라우저 | `lib/sms.ts` | 로그인 토큰을 붙여 `/api/sms`에 요청 |
| 서버 | `app/api/sms/route.ts` | 토큰 확인 → 환경 변수의 업체 키로 솔라피 호출. 키 없으면 503 안내 |
| 화면 | `components/SmsSendBox.tsx` | 받는 사람(환자/가족) 고르기, 바이트 표시, [보내기]·[취소] |
| 줄 | `HappyCallRow`, `WeeklyRow` | [문구 복사] 옆 [문자 보내기]. 성공 뒤에만 기록. 실패하면 기록 안 하고 이유 표시 |

원칙: 업체 키는 서버 환경 변수에만. 브라우저에는 anon 키만. 보내기 실패 시 기록을 남기지 않아 "보냈다고 착각"을 막는다.

## 4. 확인 항목 (qa)
- 키 없는 상태: [보내기] → "문자 설정이 아직 안 되어 있습니다" 안내, 기록 없음.
- 키 넣은 뒤 시험 환자(원장 휴대폰)로 발송 → 도착, 줄이 명단에서 빠지고 기록 메모에 문구.
- 가족 번호가 있는 환자는 받는 사람 선택이 보인다.
- 문구 46자 이상 한글 → "긴 문자(LMS)" 표시.
- 로그아웃 상태로 `/api/sms` 직접 호출 → 401.
