# 다담 접수실 앱 V3-2 3차 해피콜 설계

작성일: 2026-09-17
출처: 운영 아이디어 논의 — "연락은 됐지만 예약이 없는 환자에게 한 번 더". 사용자 결정: 금액 칸은 넣지 않고 3차 해피콜을 넣는다.

## 1. 목표
2차 해피콜(약 소진 3일 전)에서 연락은 됐지만 재처방·예약이 안 된 환자를 그냥 보내지 않는다. 일주일 뒤 한 번 더 확인해 재처방률을 올린다.

## 2. 규칙 (`lib/happyCallRules.ts`, 테스트 있음)
- 마지막 예정 건 = 2차, 또는 12일 이하 처방의 단일 건.
- 그 건을 **연락함**(전화·카톡·문자, [문자 보내기] 포함)으로 마치면 연락일 +7일에 **3차** 하나를 만든다. 메모: "연락은 됐지만 재처방·예약 없음. 예약 의사 다시 확인".
- 3차를 연락해도 4차는 만들지 않는다. 처방마다 3차는 한 번만(이미 있으면 안 만듦).
- **재처방·예약됨**으로 닫으면 그 처방의 남은 해피콜(3차 포함)이 함께 닫힌다(기존 동작). **안 받음**은 지금처럼 하루 뒤로 미룬다.
- 1차를 연락함으로 마쳐도 2차가 남아 있으므로 3차를 만들지 않는다.

## 3. 데이터
`happy_calls.round`의 제약을 1·2에서 1·2·3으로. `supabase/schema-v3-2-happycall-round3.sql`, 설정 문서 11절. 다른 표 변경 없음.

## 4. 화면
회차 배지에 "3차"가 그대로 보이고, 문구는 2차와 같은 "그다음"(남은 탕약 확인·예약 안내)을 쓴다. 달력·해피콜 명단·환자 상세 모두 회차만 다를 뿐 같은 줄이다.

## 5. 확인 항목 (qa)
- SQL 실행 → 시험 환자 20일 처방 → 2차를 연락함 저장 → 명단에 3차(+7일)가 생기고 배지 "3차".
- 3차를 연락함 저장 → 더 생기지 않음.
- 2차를 재처방·예약됨으로 닫음 → 3차 안 생김. 3차가 있는 상태에서 재처방·예약됨 → 3차도 닫힘.
