# 현재 운영 범위: 다담S(S) 전용

노원(N)은 재진콜 UI·데이터 API·DB 정책·RPC에서 차단합니다. 운영에는 schema-v12-recontact-s-only.sql만 사용합니다. 기존 일반 SQL은 참고용이며 이번 운영에 실행하지 않습니다. 기존 N 기록은 삭제하지 않습니다.

# 재진콜 안전 검증 및 운영 적용 경계

## 검증
- 전체 Vitest 22개 파일, 245개 테스트 통과(검증 브랜치 첫 커밋).
- 실제 V12 SQL을 독립된 메모리 PostgreSQL(PGlite 0.5.16)에 두 번 적용, 권한·연결·수신거부·기록 보존 등 58개 검사 통과. 실제 환자나 운영 DB를 시험에 사용하지 않음.
- 단일 연결 엔진이므로 실제 다중 연결 경합은 재현하지 않았음. 부분 고유 인덱스·트랜잭션 잠금이 마지막 방어선임.
- 로컬 실행: PGlite 모듈 경로를 PGLITE_MODULE에 지정하고 저장소 루트에서 node scripts/test-recontact-db.mjs. 필요하면 RECONTACT_TEST_REPORT로 JSON 결과 저장 경로 지정.
- 전체 lint에는 기존 app/login/page.tsx의 별개 오류 2개가 있음. CI는 이번 재진콜 변경 파일 lint를 필수 검사하며 로그인 코드는 변경하지 않음.

## 후보 기준
- 침 치료 장부 내원만으로 재진콜에서 제외하지 않음. 최근 14일 실제 한약 처방의 receive_date 기록이 있을 때만 최초 연락을 보류함.
- 같은 환자의 당일 발송·통화 기록은 보관된 후보까지 확인하여 중복 최초 연락을 막음.

## 운영 적용
운영 SQL은 별도 승인 전 실행하지 않음. 검증 브랜치는 운영 main과 분리함.
1. 기존 V11 권한 및 V10 병원별 환자 번호 고유 규칙을 사전 확인하고, 승인 후 schema-v12-recontact-s-only.sql을 한 트랜잭션으로 적용. 기존 중복/잘못된 연결이 있으면 자동 수정하지 않고 중단됨.
2. 검증된 코드를 main에 반영한 뒤 다담S·노원다담 각각 재진콜 탭과 병원별 명칭/데이터 격리 확인.
3. 연락 후보는 차트 확인 전 확정 구매자·발송 대상이 아님. 침 치료 재내원은 한약 재구매와 구별함. 업로드는 환자를 자동 생성하지 않음.
4. 병원폰 문자창은 작성 화면만 열며 실제 전송/답장 자동 동기화 기능이 아님. 발송 후 기록은 직원이 남김. 일일 한도는 앱에 기록된 사실을 기준으로 하며 외부 휴대폰 전송을 원격 통제하지 않음.
5. 문자 공급자·발신번호·자동 안내 설정은 변경하지 않음. 보관은 이력을 삭제하지 않음.
