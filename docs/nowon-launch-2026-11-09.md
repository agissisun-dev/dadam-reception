# 노원다담 접수실 개통 준비 (2026-11-09)

## 구조
- 하나의 앱: https://dadam-reception.vercel.app/
- S = 다담에스한의원, N = 노원다담한의원. 로그인 계정은 clinic_accounts로 연결한다.
- 환자/처방/해피콜/예약/장부/업무/주간관리/문구/문자 이력은 병원별 RLS로 분리한다.
- 약대장(brew_jobs, brew_weekday_rules) 및 재고(cabinet_items, cabinet_moves)만 공용이다.
- 같은 전화번호도 S/N에 각각 별도 환자로 등록한다. 병원 안에서는 중복 금지.

## 운영 DB 반영 완료
- V9 내원 경로 source/source_note (이전 배포 누락) 추가 완료.
- schema-v10-nowon-launch.sql 적용: patients 전화번호 고유 제약을 (clinic, phone)으로 변경.
- N 문구 7개, 약어 46개 준비. 환자/진료/매출 데이터는 복사하지 않음.
- N 문구의 병원명은 노원다담한의원으로 수정. 지난 추석 고정 날짜는 편집용 자리표시자로 교체.
- V8 예약문자 관련 열 추가. 자동 확인문자와 전날 리마인더는 S/N 모두 OFF 상태로 준비.
- 신규 로그인 계정은 아직 생성하지 않음. 실제 관리 가능한 노원용 이메일이 필요함.

## 약대장 안전장치
기존 브라우저 코드는 외부 병원 약대장을 옮긴 뒤, RLS 때문에 해당 처방/해피콜을 갱신하지 못하는 문제가 있었다.
- 공용 조회 및 완료/완료 취소는 양쪽 계정에서 허용.
- 일정/수령일/상세 변경과 삭제는 소속 병원 계정에서만 허용.
- DB guard_shared_brew_job 트리거가 이를 강제하고 환자/처방/장부/발효 짝의 병원 연결을 확인한다.
- 클라이언트도 최신 행/짝을 먼저 조회해 소유권 확인. 무응답 성공을 막도록 단일 행 변경 결과를 검사한다.
- 처방이 조회되지 않으면 명시적으로 실패시킨다. 개인 진료 RLS는 열지 않는다.
- 소속 병원 내 다중 API 변경은 여전히 단일 DB 트랜잭션이 아니다. 향후 양쪽 병원이 서로의 날짜를 편집해야 한다면 안전한 원자적 RPC를 별도 설계해야 한다.

- 같은 전화번호 양쪽 등록/각 병원 내부 중복 거부/환자·처방·해피콜·예약 접근 분리/상대 환자 수정 차단.
- 20일분 처방의 해피콜 2행 저장, 공용 약대장 및 재고 입출고, 공용 재고 잔량 계산.
- 타 병원 약대장 일정·삭제 차단, 완료 표시 공유, N 기본 자료 및 문자 OFF. 총 10개 DB 점검 통과.
- 기존 dates/holidays/happyCallRules/brewRules 테스트 47개를 Node native TS + strict assertion adapter로 실행: 47 통과. Vitest 정식 실행은 아님.
- lib/brew.ts 및 lib/patients.ts는 native TS 구문 검사 통과. Next.js 배포 빌드는 별도 확인.
- 기존 환자/처방/해피콜의 건수 및 전후 행 내용 fingerprint 동일. 테스트 환자는 남지 않음.
- 실제 새 N 로그인 및 UI 저장 테스트는 계정 생성 후 수행해야 함. DB 문맥 테스트를 실제 로그인 테스트로 간주하지 않는다.

## 남은 개통 단계
1. 노원 접수실용 실제 관리 가능한 이메일 지정.
2. Supabase Auth 계정 생성 후 clinic_accounts에 N으로 연결. 비밀번호는 Vault에서 생성/저장하고 문서나 채팅에 노출하지 않는다.
3. 노원 계정 로그인 시 노원다담 접수실 표시 및 환자/장부가 비어 있는지 확인.
4. 공용 약대장/재고 조회 확인 후 수신 가능한 실제 번호로 문자 테스트는 별도 승인 시에만 진행.

## 솔라피 (자동문자 연결은 후속 작업)
- 현재는 문자 발송이나 유료 테스트를 하지 않음.
- 사업자번호가 다른 병원이 가진 대표번호는 SOLAPI의 타사 발신번호 위임 등록 경로부터 검토.
- 공식 가이드: https://solapi.com/guides/senderid-delegation
- 단지 발신번호 등록 때문에 통신 명의를 먼저 바꿀 필요는 없음. 실제 가입증명원 명의와 실제 발송 주체를 확인.
- 다담에스 명의 번호를 노원다담 사업자계정에서 사용할 때 필요한 위임장/양사 관계증빙/통신서비스이용증명원 등의 인정 여부를 SOLAPI에 확인.
- 번호 명의이전은 통신사·약정·결합상품·청구 영향 확인 후 선택. 이번 작업에서 명의변경/번호이전/서류제출은 하지 않음.
