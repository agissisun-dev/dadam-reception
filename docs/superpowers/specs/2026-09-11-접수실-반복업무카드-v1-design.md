## 1. 목표와 핵심 질문

접수실이 아침에 앱을 켜면 오늘 할 일과 밀린 일이 떠 있고, 안내문을 복사해 밖에서 처리한 뒤 완료 메모를 남기면 목록에서 사라진다.

**핵심 질문:** 접수실이 아침에 이 화면만 보고, 오늘 해야 할 반복 업무와 밀린 업무를 빠짐없이 알 수 있는가.

V1은 접수실 업무에만 집중한다. 환자 정보는 다루지 않는다.

## 2. 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript + Tailwind | 2회차 투두리스트와 같은 뼈대. 배포 흐름을 이미 안다 |
| 저장소 | Supabase (PostgreSQL) — 투두리스트와 **별도 프로젝트** | 여러 PC·두 병원에서 공유. 다른 성격의 서비스라 프로젝트를 나눈다 |
| 인증 | Supabase Auth 이메일·비밀번호, **접수실 공용 계정 하나** | PC마다 한 번 로그인하면 브라우저가 기억한다. 완료자는 계정이 아니라 **이름 선택**(박정희샘·실장님·이혜경샘)으로 남긴다. 앱 내 가입 없음 |
| 접근 제어 | RLS: 로그인 사용자만 `tasks` 읽기·쓰기 | 주소를 알아도 로그인 없이는 데이터가 안 보인다 |
| 배포 | Vercel | 투두리스트와 같음 |

브라우저에서 anon 키로 Supabase에 직접 접근한다. 투두리스트처럼 service role 키를 서버 API에 두는 방식은 쓰지 않는다. RLS가 권한을 맡는다.

## 3. 화면

### ① 로그인
- 이메일, 비밀번호, [로그인] 버튼. 가입 링크 없음.
- 미로그인 상태로 다른 경로에 오면 여기로 보낸다.

### ② 오늘 할 일 (첫 화면, `/`)
- **기한 지난 일**: `due_date < 오늘` 이고 `status = todo`. 맨 위, 붉은 표시.
- **오늘 할 일**: `due_date = 오늘` 이고 `status = todo`.
- **다가오는 일 (7일)**: 접힌 상태로 아래. `오늘 < due_date <= 오늘+7`.
- 두 묶음이 모두 비면 "오늘 할 일이 없습니다" 한 줄.
- 카드: 제목, 날짜, (기한 지난 경우) 며칠 지났는지. 누르면 ③.
- 상단: [업무 등록], [지난 기록], [로그아웃].

### ③ 업무 상세 (`/tasks/[id]`)
- 제목, 날짜, 안내문 전체.
- [안내문 복사]: 클립보드에 복사하고 "복사됨" 표시 2초. **상태는 바뀌지 않는다.**
- [완료 처리]: "처리한 사람" 선택(박정희샘·실장님·이혜경샘, 마지막 선택을 브라우저가 기억)과 메모 입력란이 열림 → [저장]. `status=done`, `completed_at=now`, `completed_by=선택한 이름`, `completion_memo` 저장.
- [수정]: 제목·날짜·안내문 편집. [삭제]: 확인 창 후 실제 삭제.
- 완료된 업무를 열면 완료 정보가 보이고 [완료 취소]로 todo로 되돌릴 수 있다 (완료 정보는 비운다).

### ④ 업무 등록 (`/tasks/new`)
- 제목(필수), 날짜(필수, 기본값 오늘), 안내문(선택, 여러 줄).
- 저장하면 ②로 돌아간다.

### ⑤ 지난 기록 (`/history`)
- `status = done`을 `completed_at` 내림차순으로.
- 각 줄: 제목, 원래 날짜, 완료 시각, 완료자, 메모.

## 4. 데이터

테이블 `tasks`:

| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | bigint identity | PK |
| title | text | not null |
| due_date | date | not null |
| guide_text | text | 기본 '' |
| status | text | not null, 'todo' 또는 'done', 기본 'todo' |
| completed_at | timestamptz | null 허용 |
| completed_by | text | null 허용 (처리한 사람 이름) |
| completion_memo | text | null 허용 |
| created_at | timestamptz | 기본 now() |

RLS: `authenticated` 역할에 select/insert/update/delete 허용. `anon`은 아무것도 못 한다.

V2에서 정의·인스턴스를 나눌 때 이 표는 "올해 항목(인스턴스)"으로 남고 `template_id` 컬럼과 정의 표만 추가한다.

## 5. 오류와 예외

- 저장 실패(네트워크·권한): 화면에 "저장되지 않았습니다" 경고. 입력 내용은 유지.
- 제목·날짜가 비면 저장 버튼이 눌리지 않고 안내 문구.
- 세션 만료: 첫 화면으로 보내고 다시 로그인.
- 복사 API 실패(브라우저 권한): 안내문을 선택 상태로 만들어 수동 복사 안내.

## 6. 예시 데이터 (완료 확인용)

### 6-1. 날짜 규칙 (V1은 사람이 규칙대로 직접 입력, V2에서 자동 반복)

| 업무 | 규칙 |
|---|---|
| 다음 달 달력 카카오 채널 업로드 | 매월 25일. 휴진이면 그 전 진료일 |
| 연휴 휴진 공지 (홈페이지 · 네이버 플레이스 · 카카오 채널) | 연휴 시작 10일 전. 세 채널을 한 카드로 |
| 한방파스 재고 확인 | 명절 · 어버이날 한 달 전 |
| 명절 안내문 발송 | 4주 전, 1주 전 |

### 6-2. 실제 첫 등록 데이터

| # | 제목 | 날짜 | 상태 |
|---|---|---|---|
| 1 | 추석 연휴 휴진 공지 (홈페이지·네이버 플레이스·카카오 채널) | 2026-09-14 | todo |
| 2 | 10월 달력 카카오 채널 업로드 | 2026-09-23 | todo |
| 3 | 한방파스 재고 확인 (설 선물용) | 2027-01-07 | todo |
| 4 | 한방파스 재고 확인 (추석 선물용) | 2026-08-25 | done, 메모 "추석 전 재고 확인 완료" |

1번 안내문: 홈페이지 공지 → 네이버 플레이스 휴무일 설정 → 카카오 채널 안내 게시. 연휴 날짜와 진료 재개일을 명시.
3번 안내문: 설 연휴 전후 3일간 내원 환자 1인 1개 배포. 필요 수량 = 하루 내원 수 × 3일 + 여유분. 현재 재고를 세고 부족분 발주. 어버이날(5/8) 배포분도 4월 초에 같은 방식으로 확인.

### 6-3. 확인용 임시 데이터 (검증 후 삭제)

| 제목 | 날짜 |
|---|---|
| 확인용-어제 | 오늘 − 1 |
| 확인용-오늘 | 오늘 |

## 7. 완료 확인 (수용 기준)

1. 6-2와 6-3 등록 후 첫 화면: 기한 지난 1개(확인용-어제), 오늘 1개(확인용-오늘). 9/14·9/23은 다가오는 일(오늘이 9/11 기준, 7일 안이면). 2027-01-07은 미표시. 4번은 지난 기록에만.
2. 확인용-오늘에서 [안내문 복사] → 상태 todo 유지.
3. 확인용-오늘 [완료 처리] + 메모 → 첫 화면에서 사라지고 지난 기록에 완료자·시각·메모 표시.
4. 새로고침, 다른 브라우저(또는 다른 PC)에서 로그인 → 같은 결과.
5. Supabase Table Editor: `tasks` 6행, done 2행. 캡처를 과제 폴더에 저장.
6. 로그아웃 후 `/` 접근 → 로그인 화면.
7. 핵심 질문 판정: 1과 3이 통과하면 "됐다".
